# KV Medak BSG Portal — OYMS 4.0 (2026)

Hierarchical Online Youth Management System for **PM SHRI Kendriya Vidyalaya Ordnance Factory Medak, Eddumailaram**, KVS Hyderabad Division.

## Role hierarchy and account issue flow

1. **Super Admin** — exactly one portal-level authority. The only permitted Super Admin email is `kushalkvofmkbsgindiaoyms@gmail.com`. Public Super Admin registration is disabled. The database migration enforces one Super Admin row and restricts its email to this address. Create this one account manually in Supabase Authentication → Users using the supplied initial password, then assign its profile using the SQL below. Do not put the password in source code, SQL files, GitHub secrets committed to the repository, or browser code. Since the initial password was shared in chat, change it to a new private password before using the live portal.
2. **Vidyalaya registration** — a Vidyalaya submits its school name, KVS division / affiliation code, address, principal / authorised contact and official email. An email OTP must be verified before the application is stored as verified and pending.
3. **School / Group Admin** — only the Super Admin can approve a verified Vidyalaya application. Approval creates the Vidyalaya record, Scout Unit, Guide Company, five patrols, and activates the applicant as the School / Group Admin.
4. **Unit Leader** — the School / Group Admin creates the Scout Master / Guide Captain account for a selected Scout Unit or Guide Company. The system emails an invitation.
5. **Patrol Leader / Assistant Patrol Leader** — the Unit Leader creates both leadership accounts and assigns each to a patrol. The system emails an invitation.
6. **Unit Member** — the Unit Leader or assigned Patrol / Assistant Patrol Leader adds a Scout, Guide, Rover or Ranger and creates the member's login. The member receives an email invitation.

A role is never selected by a public applicant. The server assigns roles after an authorised approval or invitation. Login pages let users choose the account level, but the portal checks that the authenticated account actually has that role.

## Member OYMS record fields

The member record supports name, category, father's name, mother's name, date of birth, home address, PIN code, contact mobile, email / login ID, troop or company, unit address, joining date, investiture date, leaving date, role in unit, BSG UID number, unit / patrol assignment and completion dates for Pravesh, Pratham Sopan, Dwitiya Sopan, Tritiya Sopan, Rajya Puraskar and Rashtrapati.

**BSG UID is not fabricated or generated by the portal.** It is an optional field. If the UID is already known, the School Admin / Unit Leader enters it; otherwise it remains blank until the correct UID is supplied. UID approval requires a UID value.

Aadhaar is deliberately not collected in the general portal profile. It is a sensitive identifier and should only be handled through a separately authorised, legally necessary and appropriately protected process. Paper signature fields remain on the relevant printed OYMS forms.

## Supabase setup (required for real accounts)

1. Create a Supabase project.
2. Open the Supabase SQL Editor.
3. Run `supabase/schema.sql` first.
4. Then run `supabase/migrations/202611070001_oyms_hierarchy.sql`.
5. In Supabase Authentication → URL Configuration, set the Site URL and Redirect URL to the deployed GitHub Pages URL:
   `https://kushalkvofmk.github.io/BSG-OYMS-40-KV-OF-MEDAK/`
6. Configure email delivery (SMTP recommended) and the email OTP template so the email contains the one-time token (`{{ .Token }}`). Test that the message reaches the official school mailbox.
7. Deploy both Edge Functions from the repository root:
   ```bash
   supabase functions deploy approve-school
   supabase functions deploy create-role-account
   ```
8. Ensure the Edge Function runtime has `SUPABASE_URL`, `SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY`. The service-role key must remain a server-side secret and must never be added to Vite variables, frontend code, or GitHub Pages.
9. Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` as GitHub Actions repository secrets, then redeploy the website.
10. Create the first Super Admin in Supabase Authentication. Copy that user's Auth UUID and insert the initial profile in the SQL Editor:
    ```sql
    insert into public.profiles (id, full_name, email, role)
    values ('AUTH-USER-UUID', 'KV Medak OYMS Super Admin', 'kushalkvofmkbsgindiaoyms@gmail.com', 'super_admin');
    ```
    Replace `AUTH-USER-UUID` with the UUID of the one user created in Supabase Auth. Use the exact designated email above. This insert must be performed only once.

## Email onboarding test

- Register a test Vidyalaya with an email mailbox you control.
- Verify the OTP received by that mailbox.
- Confirm the application appears as pending in the Super Admin → Vidyalaya Applications page.
- Approve it. The verified applicant becomes School / Group Admin and can log in using email OTP.
- From School Admin → Create Login Accounts, create a Unit Leader.
- From Unit Leader → Create Login Accounts, create a Patrol Leader and Assistant Patrol Leader.
- From Unit Leader or assigned Patrol / Assistant Patrol Leader → Members, add a member with an email address. The member gets an invitation email.
- Enter a known BSG UID or leave it blank. Do not invent a UID. Enter it later through the authorised UID workflow.

## Patrol rules

The five school patrols are Panther, Eagle, Fox, Tiger and Lion. Each patrol has a maximum capacity of eight members. The database trigger enforces this limit as well as the interface validation.

## Development

1. Install Node.js 20 or newer.
2. Copy `.env.example` to `.env`.
3. Add the Supabase URL and anon / publishable key.
4. Run `npm install`, then `npm run dev`.

Without Supabase configuration, live registration, OTP verification, invitations and shared accounts are intentionally disabled. A local demo must never be treated as secure or as a shared school database.

## Deployment

GitHub Actions builds the Vite application and deploys `dist/` to GitHub Pages. This repository is an independent school-level BSG OYMS application, not the official KVS SAMAGAM or national BSG website.
